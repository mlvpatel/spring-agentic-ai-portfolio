## Critical Issues

### CR-01: Gateway forwards client key; backends expect different per-app keys

**Fix status:** Fixed: gateway remaps X-API-Key to per-route downstream secrets after auth.

**File:** `apps/ai-edge-gateway/src/main/java/com/portfolio/edge/filter/ApiKeyAuthGatewayFilterFactory.java:61-88`
**Also:** `apps/ai-edge-gateway/src/main/resources/application.yml:187-194`, `infra/helm/agentic-ai-portfolio/values.yaml:38-51`

**Issue:** Auth accepts only `gateway.security.apiKey` (`GATEWAY_SECURITY_APIKEY`). The filter mutates the exchange to add `X-Authenticated-User` but **does not replace** `X-API-Key` / `Authorization` with the downstream app secret. Each product app validates its own env (`YAGNI_API_KEY`, `QUALITY_GATE_API_KEY`, …). Helm/values intentionally allow **distinct** per-app keys. With distinct keys, every authenticated gateway hop returns **401 from the backend**. With a single shared key, the design works only by coincidence — not by contract. No route filter injects per-service credentials.

**Fix:**
```java
// Option A — single trust domain (document + enforce): require GATEWAY_SECURITY_APIKEY == each app key in compose/helm validation.
// Option B — preferred for multi-key: after auth, set downstream key per route:
ServerWebExchange mutated = exchange.mutate()
    .request(r -> r.headers(h -> {
        h.set("X-API-Key", downstreamApiKeyForRoute);
        h.remove(HttpHeaders.AUTHORIZATION);
        h.set("X-Authenticated-User", authenticatedUser);
    }))
    .build();
```
Wire per-route secrets from config (`gateway.routes.<id>.downstreamApiKey`) or strip backend auth and trust only cluster-network + gateway-injected principal.

### CR-02: Helm API key env names mismatch multimodal and harness apps

**Fix status:** Fixed: Helm secrets/values use MULTIMODAL_DESK_API_KEY and AI_HARNESS_API_KEY.

**File:** `infra/helm/agentic-ai-portfolio/templates/secrets.yaml:19-21`
**Also:** `infra/helm/agentic-ai-portfolio/values.yaml:267,313`
**Consumers:** `apps/multimodal-support-desk/src/main/resources/application.yml:31` (`MULTIMODAL_DESK_API_KEY`), `apps/ai-validated-integration-harness/src/main/resources/application.yml:31` (`AI_HARNESS_API_KEY`)

**Issue:** Chart injects `MULTIMODAL_API_KEY` and `HARNESS_API_KEY`. Apps bind `MULTIMODAL_DESK_API_KEY` and `AI_HARNESS_API_KEY` (compose/.env.example match the apps). Helm deploy leaves those properties empty → `ApiKeyStartupValidator` throws → pods CrashLoop. Compose is correct; Helm is wrong.

**Fix:**
```yaml
# secrets.yaml / values apiKeyEnv
MULTIMODAL_DESK_API_KEY: {{ .Values.apiKeys.multimodal | quote }}
AI_HARNESS_API_KEY: {{ .Values.apiKeys.harness | quote }}
```
Align `services.multimodalSupportDesk.apiKeyEnv` and harness `apiKeyEnv` the same way.

### CR-03: Response `mode` hard-coded `"offline"` while live ChatClient may run

**Fix status:** Fixed: services derive mode from PortfolioAiClient.isLive().

**File:** `apps/yagni-copilot/src/main/java/com/portfolio/yagni/service/YagniPatchService.java:53-69`
**Also (same pattern):** `ReviewService.java:39-44`, `CorpusService.kt:43-47`, and other services that hard-code `"offline"` while calling `portfolioAiClient.assist(...)`

**Issue:** `resolveMode()` always returns `"offline"` even when `PortfolioAiClient.isLive()` is true and `assist()` calls a remote model. Clients and tests that trust `$.mode` (e.g. `YagniCopilotApplicationTest` asserts `"offline"`) cannot detect live AI. Quality gate compounds this by saying `"LLM explanation skipped in offline mode"` while still calling `aiClient.assist(...)`.

**Fix:**
```java
private String resolveMode() {
    return portfolioAiClient.isLive() ? "live" : "offline";
}
```
Propagate the same `isLive()`-derived mode in other services; only claim “LLM skipped” when `!isLive()`.

### CR-04: MCP remote invoke builds JSON without escaping tool name

**Fix status:** Fixed: RemoteToolClient serializes invoke body with Jackson ObjectMapper.

**File:** `apps/mcp-broker/src/main/java/com/portfolio/mcpbroker/service/RemoteToolClient.java:40-76`

**Issue:** Request body is string-concatenated:
`{"name\":\"" + name + "\",\"args\":" + toJson(args) + "}"`.
Tool `name` is attacker-controlled via register/invoke APIs (after API-key auth). A name containing `"` breaks out of the JSON string and can smuggle fields into the remote sidecar payload. Map keys in `toJson` are also unescaped.

**Fix:**
```java
// Use Jackson ObjectMapper for the entire body:
record InvokeBody(String name, Map<String, Object> args) {}
String body = objectMapper.writeValueAsString(new InvokeBody(name, args == null ? Map.of() : args));
```

## Warnings

### WR-01: Redis rate limiter INCR/EXPIRE not atomic; sync I/O on Netty

**Fix status:** Fixed: Redis rate limit uses Lua INCR+EXPIRE; documented fixed-window burst.

**File:** `apps/ai-edge-gateway/src/main/java/com/portfolio/edge/ratelimit/RedisRateLimitBucketStore.java:26-34`
**Also:** `RateLimitingGatewayFilterFactory.java:48`

**Issue:** `incr` then conditional `expire` can leave keys without TTL if the process dies between calls. `connection.sync()` blocks the WebFlux event loop under load. `replenishRate` from config is ignored in Redis mode (only `burstCapacity` applies).

**Fix:** Use a Lua script (`INCR` + `EXPIRE` when count==1); switch to Lettuce async / `ReactiveRedisTemplate` in the filter. Document Redis as fixed-window (burst/sec only) or honor replenishRate.

### WR-02: In-memory rate limit clears all buckets under load

**Fix status:** Fixed: in-memory store evicts oldest buckets instead of clear-all.

**File:** `apps/ai-edge-gateway/src/main/java/com/portfolio/edge/ratelimit/InMemoryRateLimitBucketStore.java:24-30`

**Issue:** When `buckets.size() > MAX_BUCKETS`, **all** buckets are cleared — an attacker can reset everyone’s counters. Keying only on peer `remoteAddress` (no trusted-proxy policy) means behind nginx all clients share one bucket.

**Fix:** Evict LRU/oldest entries instead of `clear()`; optionally key on authenticated principal after auth.

### WR-03: OIDC path accepts any JWT that decodes for the issuer

**Fix status:** Fixed: optional oidcAudience validator; JWT decode on boundedElastic.

**File:** `apps/ai-edge-gateway/src/main/java/com/portfolio/edge/filter/ApiKeyAuthGatewayFilterFactory.java:69-76`

**Issue:** `jwtDecoder.decode(token)` validates signature/issuer/time but not audience or scopes. Any valid token from `OIDC_ISSUER_URI` becomes a full gateway principal. Decode is also blocking on the reactive stack.

**Fix:** Add audience validator; wrap decode off the event loop (`boundedElastic`) or use reactive JWT support.
